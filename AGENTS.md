When you create or rewrite an issue, use the approved issue template.
Describe the problem, why it matters, and the result you want. Keep solution choices open. Do not add acceptance criteria, completion checklists, or new requirements unless the requester supplied them. Present possible approaches as ideas. Do not turn prior art into requirements.

Keep the issue brief. Include only evidence and links that help explain or investigate this problem. Give each useful source a short note about its relevance. Omit search diaries, unrelated results, and repeated details. Distinguish observed behavior, source findings, and untested ideas. Agents must check the current code and merged work before calling a bug unresolved. Check a checklist item only when it is true. Put later progress updates and resolution details in comments. Keep the original problem or request in the issue body.

Before rewriting an issue, read its original intent and current state. Preserve the requester's explicit constraints. Do not expand the task.
